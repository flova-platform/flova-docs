Flova MCP به برنامه‌های متصل اجازه می‌دهد از طریق پروتکل زمینهٔ مدل، منابع فضای
کاری فلووا را بخوانند و تغییر دهند. ابزارهای استودیو می‌توانند داشبورد را
فهرست کنند، اطلاعات آن را بخوانند، گره‌ها و قابلیت‌های ویرایش را بررسی کنند،
تغییر را به‌صورت آزمایشی اجرا کنند، تغییر تأییدشده را اعمال کنند، پیش‌نویس را
ذخیره و اعتبارسنجی کنند و داشبورد را منتشر یا بایگانی کنند.

نشانی سرور:

~~~text
https://mcp.flova.ir/mcp
~~~

MCP برای ورود از OAuth فلووا استفاده می‌کند. برنامه در صورت نیاز مرورگر را باز
می‌کند. وارد شوید، فضای کاری فلووا را انتخاب کنید، دسترسی را تأیید کنید و اگر
برنامه خواست، نشست آن را دوباره شروع کنید.

## افزودن Flova MCP

این مثال‌ها سرور را با نام flova ثبت می‌کنند.

<Tabs items={['کدکس', 'کلود کد', 'کرسر', 'اَنتی‌گرَوِیتی', 'اُپن‌کد']} defaultIndex={0}>
  <Tab>

~~~bash
codex mcp add flova --url https://mcp.flova.ir/mcp
codex mcp list
~~~

هنگام افزودن، در صورت نیاز صفحهٔ ورود فلووا در مرورگر باز می‌شود. اگر نشست
OAuth منقضی شد، از دستور `codex mcp login flova` استفاده کنید.

  </Tab>
  <Tab>

~~~bash
claude mcp add --transport http flova https://mcp.flova.ir/mcp
claude mcp list
~~~

وقتی سرور به OAuth نیاز دارد، دستور `/mcp` را اجرا کنید. گزینهٔ
`--scope project` را فقط زمانی به کار ببرید که بخواهید فایل مشترک `.mcp.json`
برای تیم ساخته شود.

  </Tab>
  <Tab>

در پروژه فایل `.cursor/mcp.json` را بسازید یا همین سرور را به تنظیمات عمومی
برنامه اضافه کنید:

~~~json
{
  "mcpServers": {
    "flova": {
      "url": "https://mcp.flova.ir/mcp"
    }
  }
}
~~~

برنامه را دوباره بارگذاری کنید و از کنترل‌های MCP برای ورود استفاده کنید. تنظیمات
عمومی معمولاً در `~/.cursor/mcp.json` قرار دارد.

  </Tab>
  <Tab>

در منوی پنل عامل، بخش‌های سرورهای MCP، مدیریت سرورهای MCP و پیکربندی خام را باز
کنید و این ورودی را به `mcp_config.json` اضافه کنید:

~~~json
{
  "mcpServers": {
    "flova": {
      "serverUrl": "https://mcp.flova.ir/mcp"
    }
  }
}
~~~

برای اتصال HTTP جریانی از کلید `serverUrl` استفاده کنید. این فایل را می‌توانید
در `.agents/mcp_config.json` پروژه یا در `~/.gemini/config/mcp_config.json`
برای تنظیمات عمومی نگه دارید.

  </Tab>
  <Tab>

~~~bash
opencode mcp add flova --url https://mcp.flova.ir/mcp
opencode mcp list
~~~

برای همهٔ پروژه‌ها گزینهٔ `--global` را اضافه کنید. اگر ورود لازم بود، مدیر MCP
را با دستور `/mcps` باز کنید و ورود در مرورگر را کامل کنید.

  </Tab>
</Tabs>

## بررسی اتصال و ویرایش امن

از برنامهٔ متصل بخواهید منابع فضای کاری فلووا را فهرست کند یا راهنمای ویرایش
داشبورد استودیو را بخواند. برنامه فقط ابزارهایی را نشان می‌دهد که بر اساس
محدوده‌های OAuth و نقش فضای کاری اجازهٔ استفاده از آن‌ها را دارد.

برای تغییر داشبورد این ترتیب را دنبال کنید:

1. اطلاعات داشبورد را بخوانید.
2. صفحه یا گره‌هایی را که قرار است تغییر کنند، بازبینی کنید.
3. یک دستهٔ کوچک از تغییرهای معنایی آماده کنید.
4. ویرایش داشبورد را به‌صورت آزمایشی اجرا کنید.
5. همان دستهٔ موفق را با شناسهٔ عملیات و اثر انگشت پیش‌نمایش جدید اعمال کنید.
6. پیش‌نویس را ذخیره یا اعتبارسنجی کنید.
7. پیش از انتشار، داشبورد را در استودیو بررسی کنید.

برای یک ویرایش معمولی، ابزارها را به این ترتیب به کار ببرید:

1. `dashboard_authoring_context`
2. `dashboard_nodes_inspect` برای صفحه یا ویجت‌های درگیر
3. `dashboard_edit_dry_run` با ۱ تا ۱۲ تغییر معنایی
4. `dashboard_edit_semantic` با همان دستهٔ موفق، `operationId` تازه و
   `previewFingerprint` برگشتی
5. `dashboard_visual_inspect` در اندازه‌های نمایشی درخواستی
6. `dashboard_validate`
7. `dashboard_publish` با `confirm: true` فقط پس از تأیید روشن کاربر

اگر اجرای آزمایشی ناموفق بود، راهنمای `nextTool` و `repair` برگشتی را دنبال
کنید، تغییر را اصلاح کنید و همان `failureFingerprint` را دوباره نفرستید. اگر
تاریخچه ناسازگار بود، ابتدا اطلاعات تازهٔ داشبورد را بخوانید و سپس بخش درگیر را
بازبینی کنید. اگر خطای هندسهٔ واکنش‌گرا گرفتید، Grid یا Stack درگیر را بررسی
کنید و در صورت نیاز محتوا را در یک والد واکنش‌گرای کوچک‌تر تقسیم کنید.

ناسازگاری تاریخچه یعنی داشبورد بعد از خواندن برنامه تغییر کرده است. اطلاعات تازه
را بخوانید و فقط بخش‌های لازم را دوباره بررسی کنید. خطای هندسهٔ چیدمان واکنش‌گرا
یعنی Grid یا Stack نمی‌تواند محتوای درخواستی را در یک یا چند اندازهٔ نمایش جا دهد.

| بخش | نمونه |
| --- | --- |
| ویرایش کنسول | قالب، کانال داده، نگاشت، اتوماسیون و نسخه |
| ویرایش استودیو | داشبورد، صفحه، ویجت، اتصال، ظاهر، اعتبارسنجی و انتشار |
| FlovaQL | فهرست، اعتبارسنجی، اجرای پرس‌وجو و پرس‌وجوی ذخیره‌شده |
| دستگاه | فهرست دستگاه و وضعیت زمان اجرا |
| برنامه‌ریزی میان‌افزار | اطلاعات قالب و کانال‌های داده |

MCP فرمان مستقیم دستگاه، راه‌اندازی، بارگذاری میان‌افزار، انتشار OTA یا ساخت کد
فعال‌سازی را در اختیار نمی‌گذارد. عملیات حساس یا مخرب به تأیید نیاز دارند و مصرف
فراخوانی‌های MCP از سهمیهٔ طرح سازمان حساب می‌شود.

این سهمیه بین اعضای workspace مشترک است و هر ۳۰ روز بازنشانی می‌شود:

| پلن | فراخوانی MCP |
| --- | ---: |
| رایگان | ۲۵۰ |
| استارتر | ۵۰۰ |
| حرفه‌ای | ۲٬۵۰۰ |
| کسب‌وکار | ۱۰٬۰۰۰ |

صفحهٔ پلن و پرداخت در کنسول مصرف MCP دورهٔ فعلی را نشان می‌دهد. پس از پایان
سهمیه، MCP خطای `mcp_quota_exhausted` را همراه با نشانی پرداخت برمی‌گرداند.

برای دیدن رابطهٔ برنامه‌های بیرونی با دستیار داخل ویرایشگر، به [دستیار](../assistant)
برگردید.
