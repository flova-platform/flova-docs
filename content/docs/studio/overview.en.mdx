Studio is the workspace for designing dashboards for connected devices. Choose
a device template, arrange pages and widgets, connect widgets to device data,
preview the result, and publish the dashboard for the Flova web application.

Console owns device templates and datastreams. Studio uses those definitions
when it offers data sources and validates a dashboard. The web application
displays the published result for an end user.

## A useful way to think about Studio

A dashboard has three parts:

1. **Pages** define where a user goes. A dashboard can have regular pages,
   shared app layout, setup pages, and protected system pages.
2. **Widgets** display information or let a user take an action. Charts,
   gauges, tables, toggles, images, text blocks, and navigation controls all
   occupy a place on a page.
3. **Bindings and settings** connect widgets to data and define how they look
   and behave. A binding can read a datastream, write a value, or use a saved
   FlovaQL query where the widget supports it.

The editor saves a draft while you work. Users do not see a draft in the web
application until you publish it.

workspace.
