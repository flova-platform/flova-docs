Before building your first device, keep these five concepts separate. Most early problems come from treating them as the same object.

## Device Type

A Device Type is the contract for a family of devices: its datastreams, value types, access modes, and optional hardware mappings. Publishing a new version changes the contract for future configuration.

## Datastream

A datastream is one named value or command in that contract. Its technical key must stay stable because firmware, dashboards, automations, and FlovaQL all use it.

## Firmware and device

Firmware is the program running on a board. A device is the real identity created from a Device Type and activated in a workspace. Two devices can share one Device Type while having different lifecycle states and configuration generations.

## Automation

An automation is runtime logic that reacts to a datastream, schedule, or event and then performs an action. It is separate from firmware and can change without a new firmware image.

## Dashboard

A dashboard is the user experience built in Studio. Widgets bind to readable datastreams, writable datastreams, or saved queries. Publishing the dashboard makes the selected version available to the runtime.

The normal path is: define the Device Type, flash firmware, activate a device, apply configuration, bind data in Studio, and publish the dashboard.
