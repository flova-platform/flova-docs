Flova can be used at two levels. Console and Studio define the product: device types, datastreams, automations, and dashboards. The SDK and firmware run that same model on an ESP32, ESP8266, or a custom board.

You do not need every part on day one. Universal firmware is a good starting point when you want to configure a product from Console. If you already have an Arduino or proprietary firmware, keep that program and add the SDK only where you need Flova connectivity and datastreams.

## Suggested route

1. Read [Flova's mental model](/en/docs/start/mental-model) to separate device types, datastreams, devices, and dashboards.
2. Build [your first device](/en/docs/start/quickstart) with universal firmware.
3. Define names, types, and directions in [Datastreams](/en/docs/concepts/datastreams).
4. Add [automations](/en/docs/console/automations) when behavior should change without a firmware release.
5. Design the user experience in [Studio](/en/docs/studio/overview).
6. Use [FlovaQL](/en/docs/flovaql/overview) for history and charts.

## Three important choices

| Situation | Recommended path |
| --- | --- |
| You have an ESP32 or ESP8266 and want to configure behavior | Universal firmware |
| You have an existing Arduino program and need control of Wi-Fi or GPIO | Custom SDK integration |
| You have an industrial board, PLC, RTOS, or gateway | Portable C++ core with custom adapters |

The datastream names and data contract stay the same in all three cases. The firmware owner changes: universal firmware owns networking and lifecycle, while custom firmware owns the parts your application needs to control.
