Automation یک مسیر قابل‌دیدن از «چه چیزی شروع می‌کند؟» تا «چه کاری انجام
شود؟» است. آن را در canvas می‌سازید و لازم نیست برای هر تغییر کوچک firmware
را دوباره فلش کنید.

## گره‌های موجود

| دسته | گره | کاربرد |
| --- | --- | --- |
| شروع | به‌روزرسانی داده | با هر تغییر یا فقط rising/falling یک datastream شروع می‌کند |
| شروع | زمان‌بندی | یک‌بار، روزانه یا هفتگی اجرا می‌شود |
| منطق | بررسی کانال | مقدار را با شرطی مثل بزرگ‌تر یا برابر مقایسه می‌کند |
| اقدام | نوشتن در کانال | یک مقدار را set یا برای وضعیت بولی toggle می‌کند |
| اقدام | ارسال وب‌هوک | به یک نشانی HTTPS درخواست می‌فرستد |
| اقدام | ارسال هشدار | برای مالک یا کاربر دستگاه اعلان ثبت می‌کند |

## نمونهٔ عملی

برای روشن‌کردن فن وقتی دما بالا رفت:

```text
به‌روزرسانی temperature
        ↓
temperature بزرگ‌تر از 30
        ↓
نوشتن fan = true
```

برای زمان‌بندی هفتگی، timezone را همان‌جا انتخاب کنید. زمان اجرای schedule به
ساعت محلی انتخاب‌شده مربوط است، در حالی که زمان‌های ذخیره‌شده در مرزهای داده
به‌صورت دقیق و قابل‌تبدیل نگه‌داری می‌شوند.

## قبل از deploy

- trigger باید خروجی داشته باشد.
- شرط باید هم ورودی و هم خروجی داشته باشد.
- action پایان مسیر باشد.
- datastream شرط readable و datastream مقصد writable باشد.
- toggle فقط برای state بولی مناسب است.
- مقدار واردشده با نوع datastream یکی باشد.
- برای هشدار، عنوان، پیام و فاصلهٔ تکرار را تعیین کنید.

Console گراف را برای تجربهٔ ویرایش کنترل می‌کند، اما اعتبارسنجی نهایی و اجرا در
runtime انجام می‌شود. بعد از deploy، timeline و execution log را بررسی کنید و
اگر action فرمانی به دستگاه است، ACK و وضعیت دستگاه را هم ببینید.
