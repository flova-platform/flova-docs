Console is where you define and operate a connected product. Start by describing the device type and its datastreams, then create device identities and publish the configuration that firmware will use.

## Main tasks in Console

1. Create a Device Type and define its datastreams.
2. Save and publish a Device Type version.
3. Create a device activation and QR code.
4. Check connection status, latest values, and device history.
5. Build and deploy automations in the visual editor.
6. Manage compatible firmware releases and OTA updates.

Console is the product control plane. Automation execution, telemetry storage, and command delivery continue in the runtime even when the Console page is closed.

## From one workspace to many devices

Define a Device Type once and create any number of devices from its contract. Dashboards and automations can then use stable datastream keys across the whole device family. When wiring differs, keep the family contract stable and manage the hardware mapping in the Device Type version and firmware.

<Note>
The product calls this concept a “Device Type”. Some technical screens and APIs may call the same object a template.
</Note>
