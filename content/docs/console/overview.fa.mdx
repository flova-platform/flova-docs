Console جایی است که محصول متصل را تعریف و اداره می‌کنید. اینجا با دادهٔ خام
سخت‌افزار شروع نمی‌کنید؛ اول مشخص می‌کنید محصول شما چه نوع دستگاهی دارد و
کاربر نهایی چه چیزی باید ببیند یا کنترل کند.

## کارهای اصلی در Console

1. یک Device Type بسازید و datastreamها را تعریف کنید.
2. نسخهٔ Device Type را ذخیره و منتشر کنید.
3. برای دستگاه فیزیکی QR یا activation بسازید.
4. وضعیت اتصال، آخرین داده و timeline دستگاه را ببینید.
5. automation را در canvas گرافی بسازید و deploy کنید.
6. firmware release و OTA را برای target مناسب مدیریت کنید.

Console کنترل‌پنل محصول است، نه محل اجرای منطق دستگاه. اجرای automation، ذخیرهٔ
telemetry و تحویل فرمان در سرویس runtime انجام می‌شود. این جداسازی باعث می‌شود
بستن صفحهٔ Console اجرای یک automation را متوقف نکند.

## از یک workspace تا چند دستگاه

Device Type را یک‌بار تعریف کنید و هر تعداد دستگاه مجاز را با همان قرارداد
بسازید. dashboard و automation می‌توانند به نام datastreamها تکیه کنند و برای
همهٔ دستگاه‌های همان خانواده کار کنند. اگر هر دستگاه سیم‌کشی متفاوتی دارد،
mapping آن را در نسخه و firmware همان خانواده مدیریت کنید.

<Note>
در مستندات، «Device Type» اصطلاح قابل‌مشاهدهٔ محصول است. در بخش‌های فنی ممکن
است به همان مفهوم template گفته شود.
</Note>
