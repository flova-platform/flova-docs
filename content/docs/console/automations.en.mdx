---
title: "Automations and alerts"
description: "Build rules that react to channel changes, check values, write channels, and send alerts."
---

Each automation belongs to a device template. It starts with a trigger, can test a value, and then runs one or more actions. Edit it from the template's **Automations** page.

## Build an automation

1. Open [Console](https://console.flova.ir/templates), select a template, and open **Automations**.
2. Add a trigger and choose the channel or schedule that starts the rule.
3. Add a condition when the action should run only for a particular value.
4. Add an action such as a channel write, webhook request, or notification.
5. Connect the nodes in the order they should run.
6. Save the graph, then publish the template version.

The editor has these node types:

| Node | Purpose |
| --- | --- |
| Datastream update | Starts when a channel changes. Choose any change, rising, or falling. |
| Schedule | Starts once, daily, or weekly at a selected time. |
| Channel check | Compares a channel with a value. |
| Channel write | Writes a value or toggles a writable channel. |
| Webhook request | Sends an HTTP request to a configured URL. |
| Notification | Creates an alert with a title and message. |

## Use a channel trigger

Select **Datastream update**, choose a channel, and choose the trigger mode:

- **Any change** runs for every accepted update.
- **When activated** runs when a Boolean value becomes true.
- **When deactivated** runs when a Boolean value becomes false.

A channel trigger fits events such as a door opening or a temperature report changing. For a rule based on time, use **Schedule** instead.

## Check a value

Add **Channel check** after the trigger. Choose a channel, an operator, and a comparison value. Supported comparisons include equal, not equal, greater than, greater than or equal, less than, less than or equal, and changed to. Connect the condition's output to the action that should run when it passes.

Match the condition to the channel type. A numeric comparison cannot evaluate text or a structured object as a number. A Boolean condition should use `true` or `false`.

## Write to a channel or send an alert

For **Channel write**, choose a writable channel and either set a value or toggle the current value. The published channel definition must allow writes. A read-only channel makes the automation invalid.

For **Notification**, enter a title and message. Console shows the notification in its notification center. A **Webhook request** sends an HTTP request to the URL in the node, so check that the endpoint is available and that its authentication requirements are met before enabling the rule.

## Versioning and validation

Automation changes are stored with the template version. Saving the graph updates the editable version; it does not activate the new rule until you publish that version.

Before publication, Console validates that:

- every node has the fields required for its type;
- every channel still exists in the template;
- a write action points to a writable channel;
- connections form a usable path from a trigger to an action;
- values match the selected channel type.

The editor marks an invalid node and shows the message that explains what to fix. If a channel was renamed or removed, update the automation to use its new key. An older template version can also leave a rule pointing to a channel that is absent from that version.

See [Datastreams](../datastreams) for access modes and [Templates and versions](../templates) for publication behavior. Use [FlovaQL](https://console.flova.ir/flovaql) when a rule needs a query rather than a comparison against one channel.
