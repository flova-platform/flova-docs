## روش اتصال دستگاه را انتخاب کنید

| ترکیب | چه بخشی شبکه را مدیریت می‌کند؟ |
| --- | --- |
| `FlovaEsp32` یا `FlovaEsp8266` | SDK راه‌اندازی SoftAP، Wi-Fi و اتصال مجدد را مدیریت می‌کند. GPIO و حسگرها با برنامه‌اند. |
| Universal Firmware | SDK نگاشت سخت‌افزار قالب و چرخهٔ عمر Firmware را هم مدیریت می‌کند. |
| راه‌اندازی BLE در ESP32 | BLE فقط Handoff راه‌اندازی را منتقل می‌کند؛ ارتباط عادی روی شبکه است. |
| `FlovaEsp32Ethernet` | ترکیب ESP32 LAN8720 از Ethernet استفاده می‌کند؛ PHY، ساعت و پایه‌های برد را بررسی کنید. |
| `FlovaLinux` | میزبان شبکه و ناظر فرایند را مدیریت می‌کند؛ نشست دستگاه با SDK است. |
| ترکیب صریح `FlovaClient` | برنامه شبکه، راه‌اندازی، Storage و سایر سرویس‌های برد را فراهم می‌کند. |

برای اولین راه‌اندازی و تعویض Wi-Fi، [راهنمای Provisioning](../provisioning/)
و برای شبکهٔ سفارشی، [Firmware پیشرفته](../advanced/) را ببینید. کلید، نوع و
Handler دیتاستریم‌ها را مستقل از تنظیم شبکه نگه دارید.

## Flova Link و سازگاری MQTT

برای اتصال بومی SDK از Flova Link استفاده کنید. Link احراز هویت، پیوند
دیتاستریم، فرمان، گزارش، پیکربندی و اتصال مجدد را مدیریت می‌کند. کلاس‌های
مدیریت‌شدهٔ ESP در داخل از MQTT روی TLS استفاده می‌کنند و به Client جداگانه
نیاز ندارند. در `0.5.0`، سازنده‌های قدیمی PubSubClient و نمونه‌های
`begin(deviceId, deviceSecret)` دیگر پشتیبانی نمی‌شوند. از راه‌اندازی
مدیریت‌شده یا ترکیب صریح Link استفاده کنید. برای Link سفارشی،
`FlovaEsp32WithLink` یا `FlovaEsp8266WithLink` را به‌کار ببرید؛ سرویس Link
باید تا پایان عمر Facade معتبر بماند.

برای رفع خطای اتصال، اعتبارسنجی گواهی یا نام میزبان TLS را خاموش نکنید.
دسترسی شبکه، همگامی ساعت و تنظیم اعتماد را بررسی کنید. توکن، رمز Wi-Fi یا
Secret دستگاه را در گزارش‌ها ثبت نکنید.

## آمادگی اتصال را مرحله‌به‌مرحله بررسی کنید

| بررسی | چه چیزی را ثابت می‌کند؟ |
| --- | --- |
| آمادگی شبکه | برد به Wi-Fi یا Ethernet وصل است و مسیر شبکه دارد. |
| `connected()` | Transport متصل است؛ لزوماً هنوز برای کار برنامه آماده نیست. |
| `ready()` | Runtime آماده است؛ کلید و نوع هر دیتاستریم را جداگانه بررسی کنید. |
| گزارش پذیرفته‌شده | SDK عملیات را محلی پذیرفته است؛ تحویل به فلووا هنوز ثابت نشده است. |
| آخرین مقدار و تاریخچه | کنسول دادهٔ تحویل‌شده را نشان می‌دهد؛ بازهٔ زمانی تاریخچه را بررسی کنید. |

حتی هنگام قطعی، `run()` را مرتب اجرا کنید. Callbackها را کوتاه نگه دارید و
حلقه را با تأخیر طولانی متوقف نکنید. اگر برد متصل است ولی گزارشی نمی‌رسد،
نوع دستگاه منتشرشده، کلید و نوع دقیق و نتیجهٔ گزارش را بررسی کنید.

## زمان‌بندی حلقه در ESP8266

تنظیمات استاندارد BearSSL و MMU و [پروفایل آزموده‌شده](../install/) را حفظ
کنید. اتصال و نوشتن TLS ممکن است حلقه را متوقف کنند؛ Link و OTA هر دو به
بلوک پیوستهٔ کافی از Heap نیاز دارند. بافرهای بزرگ را از اسکچ حذف کنید.
وقفهٔ حلقه، Heap آزاد و بزرگ‌ترین بلوک آزاد را هنگام اتصال مجدد و OTA روی
برد اندازه بگیرید؛ کامپایل موفق کافی نیست. مسیر آپلود سیمی را حفظ کنید.
