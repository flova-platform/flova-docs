FlovaSDK برای ESP32 و ESP8266 به‌صورت Library برای Arduino و PlatformIO
منتشر می‌شود. برنامه‌های Linux از Package مربوط به CMake استفاده می‌کنند.
یک Device قابل انتقال می‌تواند Core تعبیه‌شده را با Serviceهای Platform خودش
به کار بگیرد.

FlovaSDK نسخهٔ `0.5.0` یا نسخهٔ سازگار را نصب کنید. می‌توانید [از سورس](#نصب-از-سورس)
هم نصب کنید یا برای Build در مرورگر از [Flova IDE](../ide/) استفاده کنید.

## ابتدا مدل Integration را انتخاب کنید

| چیزی که دارید | از اینجا شروع کنید | مالکیت برنامه |
| --- | --- | --- |
| Board بدون برنامهٔ Device | <code>FlovaUniversalEsp32</code> یا <code>FlovaUniversalEsp8266</code> | Template و Dashboard محصول |
| برنامهٔ موجود Arduino | <code>FlovaEsp32</code> یا <code>FlovaEsp8266</code> | GPIO، حسگر و حلقهٔ اصلی با برنامه‌اند؛ Wi-Fi و راه‌اندازی با SDK است. |
| Raspberry Pi یا Host لینوکسی | <code>FlovaLinux</code> | Process، Event Loop، Service Supervisor و Hardware |
| Board یا Gateway دیگر با C++11 | <code>flova::Device</code> | Link، Storage، Clock، Logger و اتصال Board |

برای یک Device آمادهٔ ESP32 از [شروع سریع](../quickstart/) شروع کنید. این صفحه
برای انتخاب Target، ساخت Project تازه و شناخت مرز مالکیت هر مدل است.

جدا نشوند. تب پیش‌فرض Arduino IDE است.

## Universal Firmware

`FLOVA_SETUP_PASSWORD` اختیاری است و مقدار پیش‌فرض آن `nullptr` است؛ بدون
رمز، شبکهٔ راه‌اندازی باز خواهد بود. برای محافظت از راه‌اندازی، آن را پیش از
include کردن SDK تعریف کنید یا رمز WPA اختصاصی هر دستگاه با طول ۸ تا ۶۳
کاراکتر را به سازندهٔ universal بدهید.
نسخهٔ BLE به proof of possession اختصاصی هر دستگاه با طول ۱ تا ۶۴ کاراکتر
نیاز دارد که از طریق سازنده یا `FLOVA_SETUP_PROOF_OF_POSSESSION` تنظیم می‌شود.

وقتی می‌خواهید Flova کل Composition مربوط به Device را مدیریت کند، از
Universal Firmware استفاده کنید:

~~~cpp
#include <Arduino.h>
#include <FlovaSDK.h>

FlovaUniversalEsp32 device;

void setup() {
  Serial.begin(115200);
  device.begin();
}

void loop() {
  device.run();
}
~~~

برای ESP8266 از <code>FlovaUniversalEsp8266</code> استفاده کنید. Universal
Firmware Composition برد، مسیر Provisioning، Hardware Mapping، سیاست OTA و
سیاست Restart مربوط به Target را فراهم می‌کند و برای یک محصول استاندارد
Wi-Fi کوتاه‌ترین مسیر است.

## نصب از سورس

در یک Checkout از [مخزن FlovaSDK](https://github.com/flova-platform/flova-sdk)
که نسخهٔ `0.5.0` را دارد، بستهٔ مستقل کتابخانه را بسازید:

```sh
scripts/export_sdk_release.sh "$HOME/FlovaSDK"
```

- **Arduino IDE:** پوشهٔ خروجی `FlovaSDK` را ZIP کنید و **Sketch → Include
  Library → Add .ZIP Library** را بزنید. از بستهٔ خروجی استفاده کنید، نه ZIP
  کل مخزن. اگر IDE چند کپی پیدا کرد، در خروجی Build بررسی کنید که همان بستهٔ خروجی انتخاب شده است.
- **PlatformIO:** وابستگی Registry را با مسیر خروجی جایگزین کنید؛ مثلاً
  `lib_deps = file:///home/you/FlovaSDK`. مسیر مطلق رایانهٔ خودتان و
  تنظیمات پروفایل همان برد را به‌کار ببرید.

## Linux و Raspberry Pi

Dependencyهای بومی را از ریشهٔ Repository مربوط به Firmware نصب و Package را
Build کنید:

~~~sh
sudo apt install cmake libssl-dev
cmake -S . -B build -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build build
sudo cmake --install build
~~~

Package نصب‌شده را به برنامه Link کنید:

~~~cmake
find_package(FlovaLinux CONFIG REQUIRED)
target_link_libraries(my_device PRIVATE Flova::Linux)
~~~

سپس از همان مدل Typeدار Datastream استفاده کنید:

~~~cpp
#include <FlovaLinux.h>

FlovaLinux device;
auto relay = FLOVA_DATASTREAM(device, bool, "relay");

int main() {
  if (!device.begin()) return 1;
  for (;;) device.run();
}
~~~

سازندهٔ پیش‌فرض `FLOVA_LINK_URL`، `FLOVA_DEVICE_ID` و `FLOVA_DEVICE_SECRET`
را از محیط فرایند می‌خواند. آن‌ها را از پیکربندی محافظت‌شدهٔ سرویس وارد
کنید، نه از سورس. کاربر فرایند باید اجازهٔ نوشتن در `FLOVA_STATE_DIRECTORY`
را داشته باشد (پیش‌فرض: `/var/lib/flova/device`). اگر `begin()` ناموفق بود،
پیش از شروع حلقه `lastError()` را بررسی کنید. در برنامهٔ نهایی، `run()` را
از Event Loop فراخوانی کنید؛ ثبت فرمان و Handler برنامه همگام اجرا می‌شوند.

## Boardهای قابل انتقال

Core قابل انتقال در Include عمومی خود به Arduino، ESP، Wi-Fi، File System،
Exception یا RTTI نیاز ندارد. برای Port سفارشی، این Serviceها را فراهم کنید:

<code>flova::Link</code>، <code>flova::Storage</code>، <code>flova::Clock</code>
و <code>flova::Logger</code>؛ سپس <code>flova::Device</code> را بسازید.

اگر Target به Network سفارشی، Gateway، Ethernet Chip یا Service Supervisor
نیاز دارد، [Firmware پیشرفته](../advanced/) را بخوانید.

## مراحل کامل در Arduino IDE

۱. Arduino IDE را نصب کنید. در **Tools → Board → Boards Manager** بستهٔ
**esp32 by Espressif Systems** یا **esp8266 by ESP8266 Community** را انتخاب کنید.
اگر بسته نمایش داده نشد، نشانی فهرست سازنده را در **File → Preferences →
Additional Boards Manager URLs** وارد کنید:
[ESP32](https://espressif.github.io/arduino-esp32/package_esp32_index.json) یا
[ESP8266](https://arduino.esp8266.com/stable/package_esp8266com_index.json).

۲. در **Tools → Manage Libraries**، کتابخانهٔ **FlovaSDK** نسخهٔ `0.5.0` یا
نسخهٔ سازگار جدیدتر را نصب کنید.

۳. برد را با کابل USB داده وصل کنید و برد و پورت را در **Tools → Board**
و **Tools → Port** انتخاب کنید.

۴. برای Firmware سفارشی مدیریت‌شده، **File → Examples → FlovaSDK → Basic**
را باز کنید یا از اسکچ Universal در [شروع سریع](../quickstart/) استفاده کنید.

۵. **Sketch → Upload** را بزنید. در **Tools → Serial Monitor** سرعت نمونه
را تنظیم کنید (معمولاً `115200`). پس از ظاهر شدن شبکهٔ Setup، راه‌اندازی را
از فلووا ادامه دهید.

در ESP8266، تنظیم آزموده‌شدهٔ **Tools → MMU** را حفظ کنید. TLS و OTA ممکن
است به یک بلوک پیوسته از Heap نیاز داشته باشند. اگر پورت ظاهر نشد، کابل
داده و درایور USB-Serial را بررسی کنید. هنگام خطای آپلود، سایر مانیتورهای
سریال را ببندید و برد، پورت و وضعیت Boot را بررسی کنید.

## بررسی نصب

پس از نصب و پیش از Debug منطق برنامه، هماهنگ بودن Board Package با Board
فیزیکی، تغییر کردن Serial Port هنگام جدا و وصل کردن Board، Compile شدن یک
Sketch خالی با <code>#include &lt;FlovaSDK.h&gt;</code>، یکسان بودن Class
برنامه با Target انتخاب‌شده و Publish بودن Template Device را بررسی کنید.

اگر Library پیدا می‌شود اما Device وصل نمی‌شود، Wi-Fi یا Ethernet، زمان و TLS،
وضعیت Provisioning، Session و Status Device را جداگانه بررسی کنید.
