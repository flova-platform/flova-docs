این مرجع برای Firmware و برنامه‌های Linux است. به‌جز اسکچ کامل، نمونه‌ها قطعه‌کد C++11 هستند. کلید فنی و نوع مقدار باید دقیقاً با نوع دستگاه منتشرشده یکی باشد. کلید به حروف کوچک و بزرگ حساس است. شیء دستگاه، سرویس‌های تزریق‌شده و Context هر Callback باید تا پایان استفادهٔ SDK معتبر بمانند.

## اسکچ کامل Arduino [#complete-arduino-sketch]

یک دیتاستریم Boolean قابل‌نوشتن به نام `relay` و یک دیتاستریم Number (`double`) به نام `temperature` منتشر کنید. این اسکچ ESP32 یک LED فعال با سطح HIGH روی GPIO2 را کنترل می‌کند و هر پنج ثانیه دمای شبیه‌سازی‌شده می‌فرستد.

```cpp
#include <Arduino.h>
#include <FlovaSDK.h>

FlovaEsp32 device;
auto relay = FLOVA_DATASTREAM(device, bool, "relay");
auto temperature = FLOVA_DATASTREAM(device, double, "temperature");
bool started = false;

flova::WriteResult setRelay(bool enabled) {
  digitalWrite(2, enabled ? HIGH : LOW);
  return flova::accept();
}

void setup() {
  Serial.begin(115200);
  pinMode(2, OUTPUT);
  digitalWrite(2, LOW);
  temperature.mode(flova::Mode::Sample);
  if (!relay.tryOnWrite(setRelay)) {
    Serial.println("Could not register relay");
    return;
  }
  started = device.begin();
  if (!started) Serial.println(device.lastError());
}

void loop() {
  if (!started) return;
  device.run();
  static unsigned long lastSample = 0;
  const unsigned long now = millis();
  if (now - lastSample < 5000) return;
  lastSample = now;
  const auto result = FLOVA_REPORT(temperature, 23.4);
  if (!result.accepted()) Serial.println(result.reason);
}
```

## توابع کمکی دیتاستریم [#datastream-helpers]

### `FLOVA_DATASTREAM`

`FLOVA_DATASTREAM(device, T, key)` متد `device.stream<T>(key)` را فراخوانی می‌کند. نوع‌های مجاز `bool`، `int64_t`، `float`، `double` و `flova::Text` هستند. در ESP مدیریت‌شده و Linux، ساخت Helper به‌تنهایی ثبت یا دسترسی به Storage ندارد؛ ثبت در اولین استفاده انجام می‌شود. در مقابل، درخواست Handle نوع‌دار همان لحظه کلید را Resolve می‌کند. Handler و سیاست‌ها را پیش از [`begin()`](#begin) تنظیم کنید.

```cpp
auto count = FLOVA_DATASTREAM(device, int64_t, "count");
auto label = device.stream<flova::Text>("label");
auto relayHandle = device.datastream<bool>("relay"); // ESP or portable Device
```

در Linux از `stream<T>()` یا `flovaDatastream<T>()` و در Universal ESP32 BLE از `device.device().datastream<T>()` استفاده کنید. `key()` روی Helper کلید را برمی‌گرداند؛ رشته را معتبر نگه دارید. برای `valid()`، `bound()` و `snapshot()` از [Handle نوع‌دار](#typed-handle-inspection) استفاده کنید.

### `FLOVA_WRITE`

`FLOVA_WRITE(relay, value)` همان `relay.write(value)` است. مقدار را اعتبارسنجی می‌کند و Handler را هم‌زمان با فراخوانی برای فرمان محلی اجرا می‌کند. نتیجه از نوع [`WriteResult`](#writeresult) است. رد فرمان وضعیت معتبر محلی را تغییر نمی‌دهد. اگر وضعیت از قبل اعمال شده باشد، ممکن است `NoChange` بدون اجرای Handler برگردد. دیتاستریم Sample و Event فرمان نوشتن نمی‌پذیرد.

```cpp
const auto result = FLOVA_WRITE(relay, false);
if (!result.accepted()) Serial.println(result.reason);
```

### `FLOVA_REPORT`

`FLOVA_REPORT(stream, value[, origin])` از `stream.report(value, origin)` استفاده می‌کند. مشاهده را بدون اجرای Handler ثبت می‌کند. مبدأ پیش‌فرض `flova::Origin::SensorRead` است؛ برای بازخورد فیزیکی از `PhysicalInput` استفاده کنید. پذیرش محلی رسید تحویل نیست؛ سیاست آفلاین می‌تواند گزارش را کنار بگذارد یا رد کند.

```cpp
const auto sample = FLOVA_REPORT(temperature, 23.4);
// feedbackPin is a separate input configured by the application.
const auto feedback = FLOVA_REPORT(relay, digitalRead(feedbackPin) == HIGH,
                                  flova::Origin::PhysicalInput);
if (!sample.accepted()) Serial.println(sample.reason);
if (!feedback.accepted()) Serial.println(feedback.reason);
```

### `FLOVA_HAS_VALUE`

`FLOVA_HAS_VALUE(stream)` متد `stream.hasValue()` را فراخوانی می‌کند. وجود مقدار محلی را مشخص می‌کند، نه تازگی، همگامی یا تأیید وضعیت فیزیکی را.

```cpp
if (!FLOVA_HAS_VALUE(temperature)) Serial.println("No sample yet");
```

### `FLOVA_READ`

`FLOVA_READ(stream)` همان `stream.value()` است. مقدار Cache را می‌خواند، نه پایهٔ سخت‌افزار یا Cloud را. در نبود مقدار، `T()` (مثلاً `false`، صفر یا متن خالی) برمی‌گردد. برای تشخیص نبود مقدار از [`FLOVA_HAS_VALUE`](#flova_has_value) استفاده کنید.

```cpp
if (FLOVA_HAS_VALUE(relay)) {
  const bool cached = FLOVA_READ(relay);
  Serial.println(cached ? "on" : "off");
}
```

### `FLOVA_ON_WRITE`

`FLOVA_ON_WRITE(stream, handler[, context])` همان `stream.onWrite(...)` است و برای زنجیره‌سازی، Handle را برمی‌گرداند. برای بررسی ثبت شدن از `tryOnWrite(...)` استفاده کنید. هر دو تابع یک Handler با آرگومان `T` یا Handler با `(void*, T)` همراه Context می‌پذیرند. اگر سخت‌افزار می‌تواند فرمان را رد کند، `flova::WriteResult` برگردانید؛ بازگشت `void` به‌معنی پذیرش است. فرمان راه دور در `run()` به Handler می‌رسد؛ Handler را کوتاه نگه دارید و پیش از اعمال فرمان اعتبارسنجی کنید.

```cpp
FLOVA_ON_WRITE(relay, setRelay);         // same as relay.onWrite(setRelay)
if (!relay.tryOnWrite(setRelay)) return; // in setup(), instead of the line above
```

```cpp
uint8_t relayPin = 2;
auto applyOutput = [](void* context, bool on) -> flova::WriteResult {
  const auto pin = *static_cast<uint8_t*>(context);
  digitalWrite(pin, on ? HIGH : LOW);
  return flova::accept();
};
// In setup(), after pinMode and instead of other registrations:
// if (!relay.tryOnWrite(applyOutput, &relayPin)) return;
```

### `FLOVA_SETTING`

`FLOVA_SETTING(device, T, key, fallback)` از `device.setting<T>(key, fallback)` استفاده می‌کند. روی Facadeهای ESP دارای `setting()`، `FlovaClient` یا هستهٔ قابل‌حمل، آن را پیش از `begin()` ثبت کنید. مقدار جایگزین محلی است و پس از اعمال پیکربندی، آخرین مقدار را می‌خوانید. `valid()` ثبت موفق را بررسی می‌کند، `hasValue()` برای مقدار جایگزین معتبر هم درست است و `value()` مقدار محلی یا در نبود آن `T()` را می‌دهد. خواندن تنظیمات درخواست شبکه نمی‌فرستد.

```cpp
auto threshold = FLOVA_SETTING(device, double, "threshold", 35.0);
// Equivalent: auto threshold = device.setting<double>("threshold", 35.0);
if (threshold.valid() && threshold.hasValue()) Serial.println(threshold.value());
```

پیش از استفادهٔ مقدار در سخت‌افزار، [راهنمای پیکربندی](../configuration/) را ببینید.

## رخدادهای سفارشی [#custom-log-events]

### `FLOVA_LOG_EVENT`

```cpp
bool logEvent(const char* code, const char* message = "");
```

`FLOVA_LOG_EVENT(device, code[, message])` همان `device.logEvent()` را فراخوانی
می‌کند و نتیجهٔ `bool` آن را برمی‌گرداند. این API روی `FlovaEsp32`، `FlovaEsp8266`،
`FlovaEsp32Ble`، `FlovaEsp32Ethernet` یا `FlovaClient` با Link سازگار در دسترس است.
`FlovaLinux` و هستهٔ قابل‌حمل `flova::Device` این API را ندارند.

- **کد:** ۱ تا ۳۲ بایت ASCII. با حرف کوچک انگلیسی شروع شود و در ادامه فقط حرف
  کوچک، رقم یا زیرخط داشته باشد. کد نیازی به ثبت قبلی ندارد.
- **پیام:** اختیاری، حداکثر ۹۶ **بایت** UTF-8، نه ۹۶ نویسه. رمز، توکن یا دادهٔ
  حساس را در پیام نگذارید.
- **نتیجه:** `true` یعنی SDK رخداد را در صف تک‌ظرفیتی RAM کپی کرده، نه اینکه
  Engine آن را ذخیره کرده باشد. `false` یعنی ورودی نامعتبر است، دستگاه هنوز
  راه نیفتاده یا در وضعیت خطاست، یا صف پر است. پس از موفقیت `begin()` و از کد
  عادی برنامه فراخوانی کنید، نه از تابع رسیدگی به وقفه.

حتی هنگام قطع اتصال هم `run()` را مرتب اجرا کنید. SDK تا دریافت تأیید یا رد
از Engine دوباره برای ارسال رخداد تلاش می‌کند. ارسال مجدد نسخهٔ تکراری نمی‌سازد.
با راه‌اندازی مجدد، رخداد در انتظار از دست می‌رود؛ در حافظهٔ دائمی دستگاه ذخیره
نمی‌شود. اگر `false` گرفتید، حلقهٔ دستگاه را ادامه دهید و تصمیم بگیرید که بعداً
دوباره تلاش کنید یا از آن رخداد بگذرید.

```cpp
device.logEvent("sensor_fault");
FLOVA_LOG_EVENT(device, "temperature_high", "Temperature exceeded 80 C");
```

برای بررسی تحویل رخداد در کنسول، [آموزش ثبت رخداد](../log-event/) را دنبال کنید.

## بررسی Handle نوع‌دار [#typed-handle-inspection]

سه متد اول روی `flova::Datastream<T>` و `key()` روی `FlovaDatastream<T, Client>` هستند.

| متد          | نمونه                                        | نتیجه                                                                                                                                                             |
| ------------ | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `valid()`    | `if (!relayHandle.valid()) return;`          | وجود Slot معتبر؛ کلید نامعتبر، تضاد نوع یا ظرفیت پر می‌تواند مانع ثبت شود.                                                                                        |
| `bound()`    | `if (!relayHandle.bound()) return;`          | Handle شناسهٔ Runtime دارد؛ اتصال فعال را ثابت نمی‌کند.                                                                                                            |
| `snapshot()` | `const auto state = relayHandle.snapshot();` | کپی `value`، `hasValue`، `updatedAt` (میلی‌ثانیهٔ ساعت دستگاه)، `origin`، `quality`، `dirty` (وضعیت در انتظار ارسال) و `revision`. ابتدا `hasValue` را بررسی کنید. |
| `key()`      | `Serial.println(relay.key());`               | کلید قرض‌گرفته‌شدهٔ Helper، حتی پیش از ثبت.                                                                                                                        |

## سیاست‌های دیتاستریم [#stream-policies]

پیش از شروع تنظیم کنید. متدهای زنجیره‌ای Handle را برمی‌گردانند؛ متدهای `try*` روی Handle نوع‌دار موفقیت یا شکست را گزارش می‌کنند. شکست `retention`، `persist` یا `scheduling` می‌تواند Handle نوع‌دار را نامعتبر کند. Helper تنبل ممکن است دوباره آن را Resolve کند؛ برای بررسی دقیق از Handle نوع‌دار استفاده کنید. در جدول `typed` یک Handle نوع‌دار دماست.

| متد                                                 | نمونه                                                                                                                                 | رفتار                                                                                                                                                                                           |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mode(Mode)` / `tryMode(Mode)`                      | `temperature.mode(flova::Mode::Sample);` / `const bool ok = typed.tryMode(flova::Mode::Sample);`                                      | `State` (پیش‌فرض)، `Sample` (اندازه‌گیری)، `Command` (فرمان) یا `Event` (رخداد). Sample و Event صرفاً گزارش می‌پذیرند.                                                                           |
| `offline(policy)` / `tryOffline(policy)`            | `temperature.offline(flova::OfflinePolicy::StoreHistory);` / `const bool ok = typed.tryOffline(flova::OfflinePolicy::StoreHistory);`  | `KeepLatest` (پیش‌فرض)، `StoreHistory` (تاریخچهٔ محدود)، `Drop` (بدون ارسال آفلاین)، یا `Reject` (رد عملیات آفلاین).                                                                             |
| `scheduling(Scheduling)`                            | `relayHandle.scheduling(flova::Scheduling::CloudOnly);`                                                                               | فعال کردن زمان‌بندی Console برای دیتاستریم قابل‌نوشتن. پیش‌فرض `Disabled` است. پیش از `begin()` تنظیم و سپس `relayHandle.valid()` را بررسی کنید.                                                |
| `retention(policy)` / `tryRetention(policy)`        | `temperature.retention(history);` / `const bool ok = typed.tryRetention(history);`                                                    | محدود کردن تاریخچهٔ آفلاین با `HistoryRetentionPolicy`؛ ظرفیت فیزیکی را افزایش نمی‌دهد.                                                                                                          |
| `persist(policy[, intervalMs])` / `tryPersist(...)` | `relay.persist(flova::PersistencePolicy::OnChange);` / `const bool ok = typed.tryPersist(flova::PersistencePolicy::Deferred, 30000);` | `None` (پیش‌فرض)، `Persistent`/`Immediate` (ذخیرهٔ هر به‌روزرسانی)، `OnChange` (حذف ذخیرهٔ تکراری) یا `Deferred` (مهلت از اولین تغییر ذخیره‌نشده؛ پیش‌فرض ۱۰۰۰ میلی‌ثانیه). Storage باید کار کند. |
| `flush()`                                           | `if (!relay.flush()) Serial.println("State not saved");`                                                                              | تلاش برای ذخیرهٔ فوری مقدار منتظر این دیتاستریم. نتیجهٔ موفق می‌تواند به‌معنی نبود مقدار ذخیره‌نشده باشد؛ این متد Link را تخلیه نمی‌کند.                                                          |

```cpp
flova::HistoryRetentionPolicy history;
history.maximumBytes = 4096;
history.maximumRecords = 4;
history.maximumAgeSeconds = 3600;
history.minimumIntervalMs = 60000;
history.overflow = flova::HistoryOverflow::DropOldest; // or DropNewest
temperature.offline(flova::OfflinePolicy::StoreHistory).retention(history);
```

مقدار صفر برای هر محدودیت یعنی همان محدودیت تنظیم نشده است. برای ذخیرهٔ معوق حتی آفلاین `run()` را ادامه دهید. [ماندگاری مقدار و تاریخچهٔ آفلاین](../datastreams/) دو قابلیت مستقل‌اند.

## `WriteResult`

متدهای `write()` و `report()` نتیجهٔ `flova::WriteResult { status, reason, message }` می‌دهند. `accepted()` برای `Accepted` و `NoChange` درست است. `Rejected` یعنی ورودی، سیاست یا Handler عملیات را رد کرده؛ `Failed` یعنی عملیات کامل نشد. از کد دلیل کوتاه و ثابت استفاده کنید؛ اشاره‌گر رشتهٔ محلی برنگردانید.

| تابع                                                            | کاربرد                          | نمونه                                                       |
| --------------------------------------------------------------- | ------------------------------- | ----------------------------------------------------------- |
| `flova::accept()` / `WriteResult::accept()`                     | فرمان پذیرفته شد.               | `return flova::accept();`                                   |
| `flova::unchanged()` / `WriteResult::noChange()`                | نیازی به تغییر سخت‌افزار نبود.  | `return flova::unchanged();`                                |
| `flova::reject(reason[, message])` / `WriteResult::reject(...)` | مثلاً قفل ایمنی فرمان را رد کرد. | `return flova::reject("interlock", "Output is locked");`    |
| `WriteResult::failure(reason[, message])`                       | عملیات کامل نشد.                | `return flova::WriteResult::failure("driver_unavailable");` |
| `accepted()`                                                    | بررسی هر دو وضعیت موفق.         | `if (!result.accepted()) Serial.println(result.reason);`    |

### متن و رنگ [#text-and-color-helpers]

`flova::Text(const char*)` متن محدود را کپی می‌کند؛ متن بیش از ظرفیت، مقدار خالی و نامعتبر تولید می‌کند. `valid()` اعتبار، `empty()` خالی بودن و `c_str()` اشاره‌گر معتبر تا تغییر یا نابودی شیء را می‌دهد. نوشتن یا گزارش متن نامعتبر رد می‌شود. `parseRgbHex(text, output)` قالب `#RRGGBB` را اعتبارسنجی می‌کند و `formatRgbHex(color)` متن هگز با حروف بزرگ می‌دهد.

```cpp
flova::Text text("#33aaff");
flova::RgbColor color{};
if (text.valid() && !text.empty() && flova::parseRgbHex(text, color)) {
  const auto formatted = flova::formatRgbHex(color);
  Serial.println(formatted.c_str()); // #33AAFF
}
```

## شروع و وضعیت اجرا [#startup-and-runtime-status]

### `begin()`

پس از ثبت Handlerها و سیاست‌ها، یک‌بار در شروع فراخوانی کنید. `true` یعنی چرخهٔ اجرا شروع شد، نه اینکه دستگاه وصل یا دیتاستریم‌ها پیوند داده شدند. در `FlovaClient`، `begin(false)` (پیش‌فرض) منتظر Handoff برنامه می‌ماند و `begin(true)` مسیر راه‌اندازی مدیریت‌شدهٔ تنظیم‌شده را فعال می‌کند.

```cpp
started = device.begin();
if (!started) Serial.println(device.lastError()); // Arduino facade
```

### `run()`

این متد `void` را مرتب، حتی در زمان قطعی، از حلقه‌ای فراخوانی کنید که مالک سخت‌افزار است. راه‌اندازی، اتصال مجدد، پیکربندی، فرمان و ارسال را پیش می‌برد. آن را از Interrupt یا Callback شبکه اجرا نکنید.

```cpp
void loop() {
  if (started) device.run();
}
```

| -------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| `runtimeReady()`     | همان هدف‌های `networkConnected()`                                   | `const bool inRuntime = device.runtimeReady();` — چرخهٔ اجرا در `Runtime` است، حتی اگر Link آماده نباشد.                                                         |

| `lastError()`        | Facadeهای ESP، `FlovaClient` و Linux                                | `Serial.println(device.lastError());` در Arduino یا `std::puts(device.lastError());` در Linux — پیام محدود؛ پیش از فراخوانی بعدی SDK آن را بخوانید یا کپی کنید. |
| `running()`          | Linux                                                               | `while (device.running()) { device.run(); usleep(10000); }` — شروع کامل شده، نه لزوماً اتصال.                                                                    |
| `diagnostics()`      | هستهٔ قابل‌حمل، ESP مدیریت‌شده، BLE سفارشی و `FlovaClient`           | `const auto counters = device.diagnostics();` — شمارنده‌هایی مانند `storageFailures`، `queueOverflow` و `duplicateCommands`.                                    |
| `device()`           | ESP مدیریت‌شده، Universal (از جمله BLE)، BLE سفارشی و `FlovaClient` | `auto& core = device.device();` — مرجع قرض‌گرفته‌شده به هسته؛ مستقل از Facade آن را شروع یا Poll نکنید.                                                         |

### `status()` و `setStatusListener()` [#status-and-setstatuslistener]

روی ESP مدیریت‌شده، Universal (از جمله BLE)، BLE سفارشی و `FlovaClient`، متد `status(output)` وضعیت را در `FlovaStatusSnapshot` کپی می‌کند: چرخهٔ اجرا، آمادگی، Maintenance، دلیل Restart، نسل پیکربندی و کد خطا. `setStatusListener(listener[, context])` تغییرات `run()` را با `kind`، `previous` و `current` تحویل می‌دهد. Event فقط در خود Callback معتبر است. برای لغو ثبت، `nullptr` بدهید.

```cpp
FlovaStatusSnapshot status{};
device.status(status);
device.setStatusListener([](void*, const FlovaStatusEvent& event) {
  if (event.kind == FlovaStatusEventKind::ReadyChanged)
    Serial.println(event.current.ready ? "Ready" : "Not ready");
});
// device.setStatusListener(nullptr);
```

| `restartRequired()` و `restartReason()`                         | ESP مدیریت‌شده، BLE سفارشی و `FlovaClient`                          | `if (device.restartRequired()) { const auto reason = device.restartReason(); /* record reason */ }` — نیاز به Restart، یا زمان‌بندی شدن آن، و دلیل درخواست.                                                                                                                                         |
| `prepareForPowerDown()`                                         | ESP مدیریت‌شده، Universal (از جمله BLE)، BLE سفارشی و `FlovaClient` | `if (sleepRequested && device.prepareForPowerDown() == FlovaPowerDownStatus::Ready) enterSleep();` — همراه `run()` بررسی کنید. `Busy` یعنی هنوز نمی‌تواند شروع کند؛ `Draining` یعنی در حال تخلیه؛ `Failed` یعنی تخلیه یا ذخیره ناموفق بود. تنها با `Ready` ادامه دهید؛ خاموش کردن وظیفهٔ برنامه است. |

```cpp
// In loop(), restart at a safe boundary when pendingRestart is true.
```

### به‌روزرسان Linux [#linux-ota-updater]

`flova_linux::OtaUpdater(root, activePath)` از `<FlovaLinux.h>` روی فایل‌ها کار می‌کند. هر دو مسیر را روی یک فایل‌سیستم نگه دارید. اعتبار منبع فایل، Restart و بررسی سلامت با ناظر سرویس است؛ به‌روزرسان فرایند در حال اجرا را جایگزین نمی‌کند.

| متد                                                         | نمونه                                                                                                     | رفتار                                                                                                                                       |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| سازنده                                                      | `flova_linux::OtaUpdater updater("/var/lib/flova/ota", "/var/lib/flova/bin/device");`                     | مسیر فایل‌های آمادهٔ نصب و فایل اجرایی فعال را مشخص می‌کند.                                                                                  |
| `stage(sourcePath, version, expectedBytes, expectedSha256)` | `if (updater.stage(downloadPath, version, bytes, sha256) != flova_linux::OtaStageResult::Staged) return;` | نسخه و پیشنهاد به‌روزرسانی را اعتبارسنجی می‌کند؛ اندازه و SHA-256 فایل را با دادهٔ معتبر تطبیق می‌دهد و فایل را بدون فعال‌سازی آماده می‌کند. |
| `activate(version)`                                         | `if (!updater.activate(version)) return;`                                                                 | فایل آماده را فعال و فایل جایگزین‌شده را نگه می‌دارد. ناظر باید نسخهٔ تازه را اجرا و آزمایش کند.                                             |
| `confirm(version)`                                          | `if (healthy && !updater.confirm(version)) logConfirmationFailure();`                                     | پس از بررسی سلامت توسط ناظر، نسخه را ثبت می‌کند؛ خودش سلامت را نمی‌سنجد.                                                                    |
| `rollback()`                                                | `if (!healthy && updater.rollback()) restartService();`                                                   | فایل نگه‌داشته‌شده را برمی‌گرداند؛ Restart با ناظر است. در صورت شکست، خطا را جداگانه رسیدگی کنید.                                           |

## API هستهٔ قابل‌حمل و Adapter [#portable-runtime-and-adapter-apis]

در نمونه‌ها `core` از نوع `flova::Device` است. در کد عادی Handle نوع‌دار را ترجیح دهید؛ Adapter دارای شناسهٔ پیوندخورده می‌تواند مستقیماً از API مبتنی بر شناسه استفاده کند.

| متد                                                                 | نمونه                                                                                                                                                  | رفتار                                                                                                                                                                 |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `datastreamCount()`                                                 | `const auto slots = core.datastreamCount();`                                                                                                           | شمار Slotهای تخصیص‌یافته، نه استریم‌های متصل به Cloud.                                                                                                                |
| `storageInfo([refresh])`                                            | `const auto info = core.storageInfo(true);`                                                                                                            | اطلاعاتی مثل فضای آزاد و ماندگاری؛ `true` ممکن است پرهزینه باشد و قابلیت Storage را فعال نمی‌کند.                                                                     |
| `flushPersistence()`                                                | `if (!core.flushPersistence()) return;`                                                                                                                | ذخیرهٔ همهٔ مقادیر ذخیره‌نشده؛ نتیجهٔ موفق یعنی همهٔ ذخیره‌ها انجام شدند.                                                                                                 |
| `allowCloudSchedulingForOutputs(enabled)`                           | `if (!core.allowCloudSchedulingForOutputs(true)) return;`                                                                                              | زمان‌بندی خروجی‌های دیجیتال و PWM نگاشت‌شده را پیش از شروع فعال کنید.                                                                                                 |
| `scheduling(id)`                                                    | `const auto schedule = core.scheduling(id);`                                                                                                           | سیاست زمان‌بندی شناسه؛ شناسهٔ ناشناخته `Disabled` می‌دهد.                                                                                                              |
| `originateMessageId()`                                              | `const auto messageId = core.originateMessageId();`                                                                                                    | شناسهٔ پیام خروجی از دنبالهٔ Runtime که از Nonce لینک شروع می‌شود.                                                                                                      |
| `commandResultsPending()` / `commandResultPending(id)`              | `const bool pending = core.commandResultsPending();` / `const bool awaitingAck = core.commandResultPending(commandId);`                                | انتظار نتایج فرمان برای تحویل، کلی یا برای یک شناسه. بررسی یک شناسه ممکن است Storage را بخواند و در خطای خواندن محافظه‌کارانه `true` بدهد.                            |
| `write(id, value[, origin])` / `report(id, value[, origin])`        | `auto command = core.write(id, flova::Value::from(true));` / `auto sample = core.report(id, flova::Value::from(false), flova::Origin::PhysicalInput);` | همان تفاوت فرمان و مشاهده؛ شناسهٔ ناشناخته خطاست. `Value::from` مقدار برچسب‌دار می‌سازد و `flova::validValue(value)` بازنمایی را، نه سیاست دیتاستریم را، بررسی می‌کند. |
| `setWriteHandler(id, callback, context)` / `clearWriteHandler(...)` | `if (!core.setWriteHandler(id, applyValue, context)) return;` / `const bool cleared = core.clearWriteHandler(id, applyValue, context);`                | ثبت Handler از نوع `WriteResult(void*, const Value&)`؛ حذف به همان Callback و Context نیاز دارد. برای Handle نوع‌دار، `tryOnWrite` را ترجیح دهید.                     |
| `setFactoryResetHandler(handler, context)`                          | `core.setFactoryResetHandler(resetFromCommand, context);`                                                                                              | Handler از نوع `WriteResult(void*, const char*)` برای فرمان Reset مجاز که شناسهٔ فرمان را دریافت می‌کند.                                                               |
| `validateConfigurationUnit(unit)` / `applyConfigurationUnit(unit)`  | `if (core.validateConfigurationUnit(unit)) { const bool applied = core.applyConfigurationUnit(unit); /* handle failure */ }`                           | اعتبارسنجی و اعمال یک واحد Decode‌شده. این دو جایگزین چرخهٔ کامل و تراکنشی پیکربندی نیستند.                                                                            |
| `detachLink()`                                                      | `core.detachLink();`                                                                                                                                   | ابتدا Poll برنامه را متوقف و سپس Callbackهای Link قرض‌گرفته‌شده را جدا کنید. ## API تایمر محلی [#local-timer-api]

از `<FlovaScheduler.h>` استفاده کنید. `flova::Scheduler(wallClock)` یک `WallClock` از برنامه قرض می‌گیرد. `synchronized()` معتبر بودن ساعت را اعلام می‌کند و `localTime(timezone, output)` یک `flova::LocalTime` را پر می‌کند یا `false` می‌دهد. `daily(hour, minute, timezone, handler[, weekdays])` برای ورودی نامعتبر یا پر شدن هشت جایگاه، `false` می‌دهد. بیت صفر برای یکشنبه تا بیت شش برای شنبه است؛ پیش‌فرض هر روز است. رشتهٔ منطقهٔ زمانی را معتبر نگه دارید. `run()` در دقیقهٔ مقرر و حداکثر یک‌بار در هر تاریخ برای هر تایمر (در RAM) اجرا می‌کند؛ زمان ازدست‌رفته جبران نمی‌شود. پس از روشن شدن دوباره، تایمرها را ثبت کنید.

```cpp
#include <FlovaScheduler.h>

flova::Scheduler timers(wallClock); // supplied by the application
void turnOff() {
  const auto result = relay.write(false);
  if (!result.accepted()) Serial.println(result.reason);
}

// In setup(): Monday through Friday, at 20:00 local time.
// if (!timers.daily(20, 0, "IRST-3:30", turnOff, 0x3e)) return;
// In loop(): call timers.run() alongside device.run().
```

این API از [زمان‌بندی ابری](../scheduling/) مستقل است.
