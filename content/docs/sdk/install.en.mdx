FlovaSDK is distributed as an Arduino and PlatformIO library for ESP32 and
ESP8266. Linux applications use the CMake package. A portable device can use
the embedded core with its own platform services.

Install FlovaSDK `0.5.0` or a compatible release. You can also [install from
source](#install-from-source) or build in the browser with [Flova IDE](../ide/).

## Pick the integration model first

| You have | Start with | The application owns |
| --- | --- | --- |
| A board and no device application | `FlovaUniversalEsp32` or `FlovaUniversalEsp8266` | Your template and product dashboard |
| An existing Arduino application | `FlovaEsp32` or `FlovaEsp8266` | GPIO, sensors, and the main loop; the SDK owns setup and Wi-Fi |
| A Raspberry Pi or Linux host | `FlovaLinux` | The process, event loop, service supervisor, and hardware |
| Another C++11 board or gateway | `flova::Device` | Link, storage, clock, logger, and board integration |

Use the [Quick start](../quickstart/) if you want a working ESP32 device first.
Use this page when you need to select a target or set up a new project.

## Universal firmware

`FLOVA_SETUP_PASSWORD` is optional and defaults to `nullptr` (an open setup AP).
For protected setup, define it before including the SDK, or pass a device-unique
8–63 character WPA password to the universal constructor. BLE compositions
require device-unique proof of possession through their constructor or
`FLOVA_SETUP_PROOF_OF_POSSESSION` (1–64 characters).

Use a universal composition when Flova should own the complete device image:

```cpp
#include <Arduino.h>
#include <FlovaSDK.h>

FlovaUniversalEsp32 device;

void setup() {
  Serial.begin(115200);
  device.begin();
}

void loop() {
  device.run();
}
```

For ESP8266, use `FlovaUniversalEsp8266`. Universal firmware includes the board
composition, setup path, hardware mapping, OTA policy, and restart policy
provided by that target. It is the shortest path for a standard Wi-Fi product.

## Install from source

From a [FlovaSDK checkout](https://github.com/flova-platform/flova-sdk) that
contains `0.5.0`, create the standalone library:

```sh
scripts/export_sdk_release.sh "$HOME/FlovaSDK"
```

- **Arduino IDE:** ZIP the exported `FlovaSDK` folder, then choose **Sketch →
  Include Library → Add .ZIP Library**. Use the exported package, not a ZIP
  of the whole repository. If Arduino IDE finds multiple copies, check the
  build output to confirm it selected the exported library.
- **PlatformIO:** Replace the registry `lib_deps` entry with the path to the
  export, such as `lib_deps = file:///home/you/FlovaSDK`. Use the absolute path
  on your machine and keep the board settings from the matching profile.

## Linux and Raspberry Pi

Install the native dependencies and build the package from the firmware
repository:

```sh
sudo apt install cmake libssl-dev
cmake -S . -B build -DCMAKE_INSTALL_PREFIX=/usr/local
cmake --build build
sudo cmake --install build
```

Link the installed package from your application:

```cmake
find_package(FlovaLinux CONFIG REQUIRED)
target_link_libraries(my_device PRIVATE Flova::Linux)
```

Then use the same typed datastream model:

```cpp
#include <FlovaLinux.h>

FlovaLinux device;
auto relay = FLOVA_DATASTREAM(device, bool, "relay");

int main() {
  if (!device.begin()) return 1;
  for (;;) device.run();
}
```

The default constructor reads `FLOVA_LINK_URL`, `FLOVA_DEVICE_ID`, and
`FLOVA_DEVICE_SECRET` from the process environment. Supply them through your
service's protected configuration rather than compiling them into the program.
The process user needs writable access to `FLOVA_STATE_DIRECTORY` (default
`/var/lib/flova/device`). If `begin()` fails, check `lastError()` before
starting the loop. In production, call `run()` from your poll or event loop;
command checkpoints and application handlers run synchronously.

## Portable boards

The portable core has no Arduino, ESP, Wi-Fi, filesystem, exception, or RTTI
requirement in its public include path. A custom port supplies
`flova::Link`, `flova::Storage`, `flova::Clock`, and `flova::Logger`, then
constructs `flova::Device`.

Use [Advanced firmware](../advanced/) when the target needs a custom network,
gateway, Ethernet chip, or service supervisor.

## Installation checks

After installation, check the following before debugging application logic:

1. The board package matches the physical board.
2. The selected serial port changes when you unplug and reconnect the board.
3. The project can compile an empty sketch with `#include <FlovaSDK.h>`.
4. The selected target matches the class in the sketch.
5. The device has a published template before it tries to bind datastreams.

If the library is found but the board does not connect, inspect Wi-Fi readiness,
time or TLS readiness, provisioning state, and the device status separately.

## Arduino IDE: complete walkthrough

Use this path when you want to compile and upload from the Arduino IDE rather
than PlatformIO.

1. Install the latest Arduino IDE.
2. Open **Tools → Board → Boards Manager** and install the board package for
   your target: **esp32 by Espressif Systems** or **esp8266 by ESP8266
   Community**. If the package does not appear, add the vendor index under
   **File → Preferences → Additional Boards Manager URLs**:
   [ESP32](https://espressif.github.io/arduino-esp32/package_esp32_index.json)
   or [ESP8266](https://arduino.esp8266.com/stable/package_esp8266com_index.json).
3. Open **Tools → Manage Libraries**, search for **FlovaSDK**, and install
   version `0.5.0` or the latest compatible release.
4. Connect the board with a USB data cable. Select the physical board under
   **Tools → Board** and its serial device under **Tools → Port**.
5. Open **File → Examples → FlovaSDK → Basic** for managed custom firmware, or
   use the universal sketch in [Quick start](../quickstart/).
6. Select **Sketch → Upload**. Open **Tools → Serial Monitor**, set the speed
   printed by the example (normally `115200`), and complete provisioning from
   Flova when the setup network appears.

For ESP8266, keep the board's tested **Tools → MMU** setting and avoid adding
large buffers to the sketch. TLS and OTA can temporarily require a contiguous
heap block. If no port appears, install the board's USB-serial driver, try a
data cable, and reconnect the board. If upload fails, close other serial
monitors and confirm the selected board, port, and boot mode.
