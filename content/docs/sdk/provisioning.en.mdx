Provisioning has two separate data: network information and short-term handoff to reach
FlovaLink. In universal firmware, Flova manages both parts in the setup flow.
In custom firmware, application owns Wi-Fi and server, and SDK only owns handoff.
Receives and consumes.

## custom Arduino with existing server

If your application already has `WebServer`, SDK will not replace it. Routes
Register the setup limit on your server:
```cpp
client.attachProvisioning(server);
server.begin();
```
This helper adds local paths `GET /status` and `POST /provision`.
application still `server.handleClient()` and `client.run()` in its own loop
calls

## independent handoff from Wi-Fi

For BLE, serial, Ethernet, cellular or factory tool, your channel data to
Convert Flova handoff:
```cpp
flova::ProvisioningHandoff handoff(linkUrl, shortLivedToken);
client.provision(handoff);
```
The handoff only carries the valid Link URL and the short-lived token. The secret of the device must be
be made in the device itself. Do not put the network credential in portable handoff;
It is owned by your universal composition or application.

## Successful cycle

1. The channel delivers the handoff.
2. SDK restricts and saves it.
3. The device goes to the network and bootstraps.
4. Receives, checks and stabilizes the configuration.
5. After restart, it reports the applied generation.

Token or credential storage alone is not successful in provisioning. If device after
setup online failed, first check Wi-Fi, then Link and then configuration separately
do

## Viewing the result in the program

For an application that needs to synchronize its UI, LED, or retry with the SDK state, from
Use `setStatusListener()`. Events are edge-triggered and from
`client.run()` are called; Disconnect network, disconnect Flova Link, reach runtime,
Configuration generation change and errors have separate events. callback should not
network or run another long task on the spot.

To recognize the current stage, do not confuse these boundaries:

- `networkConnected()` only shows local network connection.
- `connected()` shows the Flova Link.
- `provisioning()` indicates that SDK is still in setup/provisioning or handoff.
- `ready()` means runtime and device binding are ready for datastreams.

The last snapshot can be read without waiting for the event:
```cpp
FlovaStatusSnapshot status = {};
client.status(status);
Serial.printf("network=%u link=%u ready=%u generation=%lu\n",
              status.networkConnected ? 1U : 0U,
              status.linkConnected ? 1U : 0U,
              status.ready ? 1U : 0U,
              static_cast<unsigned long>(status.configurationGeneration));
```
`status.errorCode` only provides limited error code to the application; tokens
Do not log the full credential and payload. Complete example of listener registration in
[SDK Quick Start](/en/docs/sdk/quickstart) has arrived.
