## زمان‌بندی ابری

زمان‌بندی ابری در فلووا اجرا می‌شود و در موعد مقرر یک فرمان نوشتن عادی
می‌فرستد. دستگاه باید آنلاین باشد. نوبت‌های ازدست‌رفته اجرا نمی‌شوند و
فرمان ۶۰ ثانیه پس از موعد منقضی می‌شود. بررسی‌های ایمنی Firmware همچنان
اعمال می‌شوند و هیچ زمان‌بندی‌ای روی دستگاه دانلود نمی‌شود.

در Firmware سفارشی، هر دیتاستریم قابل‌نوشتن را پیش از `begin()` فعال کنید:

```cpp
relay.scheduling(flova::Scheduling::CloudOnly);
```

پیش‌فرض `flova::Scheduling::Disabled` است. کنسول اجازه‌ای را که Firmware
نداده فعال نمی‌کند. Universal Firmware خروجی‌های دیجیتال و PWM پیکربندی‌شده
را فعال می‌کند، نه ورودی‌ها. [اتوماسیون کنسول](../../console/automations/) را ببینید.

## تایمر محلی

برای کارهایی مثل خواندن حسگر هر پنج ثانیه یا اجرای یک‌باره پس از تأخیر،
[آموزش تایمر فاصله‌ای](../timers/) را ببینید. برای اجرای کار در ساعت مشخصی
از روز، از زمان‌بندی زیر استفاده کنید.

[API تایمر محلی](../reference/#local-timer-api) امضای متدها و نمونهٔ محدود کردن روزهای اجرا را نشان می‌دهد.

برای اجرای کار بدون شبکه، از `flova::Scheduler` استفاده کنید. برنامه یک
`flova::WallClock` همگام و تبدیل منطقهٔ زمانی فراهم می‌کند. با فرض وجود
`wallClock` و دیتاستریم `relay`:

```cpp
#include <FlovaScheduler.h>

flova::Scheduler timers(wallClock);
void turnOff() { relay.write(false); }

// In setup():
// timers.daily(20, 0, "IRST-3:30", turnOff);
// In loop(), alongside device.run():
// timers.run();
```

تایمر به ساعت معتبر نیاز دارد و فقط در دقیقهٔ مقرر اجرا می‌شود. حداکثر هشت
تایمر و وضعیت اجرای آن‌ها در RAM نگه‌داری می‌شوند؛ پس از راه‌اندازی مجدد
آن‌ها را دوباره ثبت کنید. روشن‌شدن مجدد در همان دقیقه ممکن است عمل را
تکرار کند. Handler را طوری بنویسید که تکرار بی‌خطر باشد و نوشتن را از API
دیتاستریم انجام دهید. یک عمل را در کنسول و دستگاه هم‌زمان تعریف نکنید، مگر
اینکه اجرای هر دو عمدی باشد.
