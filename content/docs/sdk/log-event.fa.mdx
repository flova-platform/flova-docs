از `logEvent()` برای رخدادهایی مثل خرابی حسگر، باز شدن در یا عبور یک مقدار
از آستانه استفاده کنید. برای اندازه‌گیری‌های دوره‌ای یا نمایش مقدارها در نمودار،
از [دیتاستریم](../datastreams/) استفاده کنید. ثبت رخداد به‌تنهایی هشدار نمی‌فرستد.
برای دریافت هشدار، [رخداد را به اتوماسیون فضای کاری وصل کنید](../event-alerts/).

## ۱. دستگاه را آماده کنید

یک برد ESP32 یا ESP8266 با فریم‌ور Arduino و نسخه‌ای از FlovaSDK که `logEvent()`
را دارد لازم است. اگر فلووا را روی سرور خودتان اجرا می‌کنید، پیش از آپلود اسکچ
Engine و کنسول را به‌روز کنید. فریم‌ور پیش از ارسال بررسی نمی‌کند که Engine از
این رخداد پشتیبانی می‌کند یا نه.

از یک نوع دستگاه منتشرشده استفاده کنید. اگر برد هنوز به فلووا وصل نشده،
[مراحل راه‌اندازی دستگاه](../provisioning/) را دنبال کنید. نیازی به ثبت کد رخداد،
افزودن دیتاستریم، حسگر یا سیم‌کشی نیست.

## ۲. اسکچ را روی برد آپلود کنید

این اسکچ را با [Arduino IDE یا PlatformIO](../install/) آپلود کنید. روی ESP8266،
به‌جای `FlovaEsp32` از `FlovaEsp8266` استفاده کنید. اگر نمونه را به اسکچ فعلی
اضافه می‌کنید، فراخوانی‌های `begin()` و `run()` را نگه دارید.

```cpp
#include <Arduino.h>
#include <FlovaSDK.h>

FlovaEsp32 device;
bool started = false;

void setup() {
  Serial.begin(115200);
  started = device.begin();
  if (!started) {
    Serial.println(device.lastError());
    return;
  }

  if (!FLOVA_LOG_EVENT(device, "application_started", "Custom sketch started")) {
    Serial.println("Could not queue application_started");
  }
}

void loop() {
  if (started) device.run();
}
```

تابع کمکی `device.logEvent()` را فراخوانی می‌کند و رخداد را پیش از آماده شدن
شبکه در صف می‌گذارد. `device.run()` را مرتب فراخوانی کنید تا دستگاه وصل شود و
رخداد را بفرستد. این اسکچ پس از هر بار روشن یا راه‌اندازی مجدد شدن دستگاه یک
رخداد در صف می‌گذارد. برای ارسال کد بدون پیام، به‌جای آن از
`device.logEvent("application_started")` استفاده کنید.

## ۳. رخداد را در کنسول ببینید

۱. در کنسول، نوع دستگاه را باز کنید و به [پایش](../../console/monitor/) بروید.

۲. در فهرست رخدادها، فیلتر **Event type** را روی **Custom events** بگذارید و
دستگاه را انتخاب کنید. از **Live** یا بازه‌ای استفاده کنید که زمان اتصال دستگاه
را پوشش دهد.

۳. دنبال `application_started: Custom sketch started` بگردید و برای دیدن جزئیات،
ردیف رخداد را باز کنید.

اگر رخداد را نمی‌بینید، آنلاین بودن دستگاه و بازهٔ زمانی را بررسی کنید و در
Serial Monitor با سرعت `115200` دنبال خطای راه‌اندازی یا خطای صف بگردید. اگر
رخدادهای بیشتری به اسکچ اضافه می‌کنید، مقدار برگشتی را بررسی کنید: صف فقط یک
جای خالی برای رخداد سفارشی دارد. هنگام تغییر وضعیت رخداد ثبت کنید، نه در هر
بار اجرای `loop()`.

محدودیت ورودی‌ها و رفتار دستگاه در زمان قطع اتصال یا راه‌اندازی مجدد در
[مرجع API](../reference/#flova_log_event) آمده است.
