## Choose how the device connects

| Integration | Who owns networking? |
| --- | --- |
| `FlovaEsp32` or `FlovaEsp8266` | SDK manages SoftAP setup, Wi-Fi and reconnects. Your sketch owns GPIO and sensors. |
| Universal firmware | SDK also applies template hardware mappings and manages firmware lifecycle. |
| ESP32 BLE setup | BLE carries the setup handoff; runtime traffic uses the network, not BLE. |
| `FlovaEsp32Ethernet` | The ESP32 LAN8720 composition uses Ethernet; check the board's PHY, clock and pin configuration. |
| `FlovaLinux` | The host owns networking and the process supervisor; the SDK handles the device session. |
| Explicit `FlovaClient` composition | Your application provides networking, setup, storage and other board services. |

See [Provisioning](../provisioning/) for first boot and Wi-Fi replacement and
[Advanced firmware](../advanced/) for custom networks. Keep datastream keys,
types, and handlers independent of network setup.

## Flova Link and MQTT compatibility

Use Flova Link for native SDK integrations. Link handles authentication,
datastream binding, commands, reports, configuration, and reconnection. The
managed ESP facade uses MQTT over TLS internally; you do not supply a broker
client. In `0.5.0`, the old PubSubClient constructors and
`begin(deviceId, deviceSecret)` examples are no longer supported. Move to
managed setup or an explicitly composed Link integration. If you supply your own
Link implementation, use `FlovaEsp32WithLink` or `FlovaEsp8266WithLink`; the
injected service must outlive the facade.

Do not disable TLS certificate or hostname verification to resolve a connection
problem. Check network access, clock synchronization, and trust configuration
instead. Never log claim tokens, Wi-Fi passwords, or device secrets.

## Diagnose readiness in order

| Check | What it proves |
| --- | --- |
| Network ready | The board has joined Wi-Fi or Ethernet and has a usable network path. |
| `connected()` | The Link transport is connected, not necessarily ready for application traffic. |
| `ready()` | The runtime is ready; verify each stream's key and type separately. |
| Accepted report | The SDK accepted the operation locally. This is not proof of cloud delivery. |
| Latest value and history | Console confirms what actually reached Flova. Check the selected time range for history. |

Call `run()` frequently, including during an outage. Keep callbacks short and
avoid long delays in the loop. If the board connects but reports are missing,
verify the published Device Type, exact key and value type, and report result.

## ESP8266 timing

Use the stock BearSSL and MMU settings and the [tested profile](../install/).
TLS connect and writes can block the loop, and both Link and OTA need a
sufficiently large contiguous heap block. Keep large buffers out of the sketch.
Measure loop gaps, free heap and largest free block during reconnects and OTA
on your board; a successful compile does not verify timing or available heap.
Keep a wired upload path available.
