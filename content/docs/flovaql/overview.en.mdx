FlovaQL is a small semantic language for reading FLOVA data. Its query form for
The user is similar to SQL, but it is not SQL and does not give access to the table or the internal name of the database.
You select dataset, field and datastream from the general catalog and Engine
It performs the rest of the access, type, and scope checks.

FlovaQL is read-only. To change state or send command from dashboard, API or
Use automation.

## Original datasets

| dataset | Application | Index fields
| --- | --- | --- |
| `devices` | List and status of devices `id`, `name`, `status`, `last_seen_at` |
| `datastreams` | Defining the channels of a Device Type | `key`, `name`, `data_type`, `mode`, `unit` |
| `telemetry` | Reported time values `time`, `value`, `device_id`, `unit` |
| `events` | Events and warnings `time`, `key`, `severity`, `message` |
| `commands` | The status of sent commands `time`, `datastream_key`, `status`, `acked_at` |

To see the workspace catalog, use the path related to Console or API. field
Do not guess, especially when the Farsi name of a device is different from its technical key.

In saved queries Studio, you can set the text parameter `deviceId` with
Define `builtin: device.id`. Runtime injects its value from the current device
and Engine queries `devices`, `telemetry`, `events` and `commands` to the same device
limits This behavior does not exist for enterprise query Console or MCP; It should be there
Filter the device with the validated catalog value.

## A simple query
```sql
SELECT id, name, status, last_seen_at
FROM devices
WHERE status = 'offline'
ORDER BY last_seen_at DESC
LIMIT 100
```
For telemetry you must have a time frame:
```sql
SELECT time, value
FROM telemetry
WHERE datastream.key = 'temperature'
  AND time > now() - 24h
ORDER BY time ASC
LIMIT 1000
```
`telemetry.key` alone is not enough. In most real queries, from qualifiers
Use something like `datastream.key` or `device.name` to clear the relationship.

## query response

The result is a typed table: `columns` describes the type and name of the columns, and `rows`
It has the value of each row. Metadata also run time, number of rows, effective timezone and so on
Expresses the status of the cache. Times for interchange as ISO-8601 with `Z`
they return; timezone is only used for bucket and display alignment.
