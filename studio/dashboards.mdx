# داشبورد و layout

یک داشبورد خوب از دادهٔ واقعی شروع می‌کند، نه از کارت‌های تزئینی. صفحه را با
یک هدف مشخص بسازید: مشاهده، کنترل، هشدار یا تنظیمات.

## قواعد عملی

- widgetهای مرتبط را در یک hierarchy روشن قرار دهید.
- برای موبایل و دسکتاپ breakpoint مستقل اما semantics مشترک داشته باشید.
- وضعیت `loading`، `empty`، `stale` و `error` را طراحی کنید.
- برای فرمان‌های خطرناک تأیید و نتیجهٔ قابل‌مشاهده نشان دهید.
- زمان‌ها را با timezone کاربر نمایش دهید و مقدار UTC را در API نگه دارید.

<Tip>
اگر یک widget نمی‌داند مقدارش از کدام datastream می‌آید، binding آن کامل نیست.
</Tip>
