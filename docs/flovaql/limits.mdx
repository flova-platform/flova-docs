# محدودیت‌ها و خطاها

FlovaQL پیش از اجرا query را از نظر مجوز، زمان، پیچیدگی، تعداد ردیف و اندازهٔ
نتیجه بررسی می‌کند. نتیجهٔ ناقص با truncate خاموش تولید نمی‌شود؛ query باید
با محدودیت سازگار شود.

## نکته‌های مهم

- queryهای telemetry، event و command history به بازهٔ زمانی محدود نیاز دارند.
- retention بر اساس entitlement سازمان تعیین می‌شود.
- query جزئیات خام بازهٔ کوتاه‌تری از aggregateهای طولانی دارد.
- timezone برای bucket مهم است؛ timestamp wire همیشه UTC و با `Z` است.
- خطای قابل‌نمایش باید code پایدار و توضیح انسانی داشته باشد.

برای query طولانی‌تر، datastream مشخص انتخاب کنید، bucket مناسب بدهید و row
limit را از پیش تخمین بزنید.
