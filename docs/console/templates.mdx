# ساخت محصول و دیتاستریم

## یک Template بسازید

برای هر خانوادهٔ دستگاه نام و توضیح انسانی انتخاب کنید. Template محل تعریف
قرارداد است، نه محل نگهداری مقدارهای لحظه‌ای یک دستگاه.

## دیتاستریم اضافه کنید

برای هر دیتاستریم این سؤال‌ها را پاسخ دهید:

1. کلید پایدار آن چیست؟
2. مقدار `boolean`، `double` یا `string` است؟
3. دستگاه آن را می‌خواند، می‌نویسد یا هر دو؟
4. واحد، بازهٔ معتبر و رفتار خطا چیست؟
5. به کدام پایه یا منطق سخت‌افزاری متصل می‌شود؟

## Publish

پیش از انتشار، نبودن کلید تکراری، نوع درست، mapping معتبر و graph قابل‌اجرا را
بررسی کنید. پس از publish، دستگاه‌ها قرارداد همان نسخه را دریافت می‌کنند.

<Warning>
دیتاستریم را فقط به‌خاطر تغییر label فارسی حذف نکنید. کلید فنی بخشی از قرارداد
فریم‌ور و API است.
</Warning>
