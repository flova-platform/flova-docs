Device Type توضیح می‌دهد یک خانوادهٔ دستگاه چه داده‌ها و قابلیت‌هایی دارد.
دستگاه‌های واقعی از یک Device Type ساخته می‌شوند، اما هر دستگاه هویت، وضعیت،
firmware و نسخهٔ پیکربندی خودش را دارد.

## چه چیزهایی در Device Type قرار می‌گیرد؟

- datastreamها، نوع مقدار، واحد، بازه و mode
- mapping ورودی و خروجی برای firmwareهای universal
- مقدار پیش‌فرض و محدودیت‌های قابل‌نمایش در UI
- automationهای همان خانواده
- نسخه‌ای که می‌تواند به دستگاه‌های آن خانواده اعمال شود

mapping سخت‌افزار را با کلید datastream قاطی نکنید. `relay` قرارداد محصول است؛
اینکه روی GPIO2 یا یک خروجی PLC قرار دارد، تصمیم firmware یا Device Type است.
در custom firmware ممکن است mapping را اصلاً در Console نگذارید و آن را در
کد برنامه نگه دارید.

## چرا نسخه داریم؟

وقتی یک datastream اضافه یا محدودیت آن عوض می‌شود، دستگاه‌های موجود نباید
ناگهان با قراردادی ناشناخته کار کنند. Console تغییرات را در یک نسخه نگه
می‌دارد و دستگاه نسخهٔ مطلوب و نسخهٔ اعمال‌شدهٔ خودش را گزارش می‌کند.

قبل از انتشار نسخه:

1. نام کلیدهای قبلی را حفظ کنید.
2. mode و نوع مقدار را با widgetها و automationهای موجود مقایسه کنید.
3. mappingهای universal را روی برد واقعی بررسی کنید.
4. یک دستگاه آزمایشی را به نسخهٔ جدید ببرید.
5. پس از اطمینان، نسخه را برای بقیه منتشر کنید.

<Warning>
تغییر نام `key` شبیه ساختن یک کانال تازه است. اگر فقط عنوان کاربر را می‌خواهید
تغییر دهید، `name` را عوض کنید و کلید فنی را ثابت بگذارید.
</Warning>
