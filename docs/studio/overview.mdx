Studio ویرایشگر visual فلوواست. dashboard را مثل یک صفحهٔ محصول می‌سازید، اما
مقدارها و فرمان‌ها از Device Type و دستگاه انتخاب‌شده می‌آیند. این یعنی همان
تجربه می‌تواند روی وب، PWA و اپ موبایل با layout مناسب هر صفحه اجرا شود.

## ذهنیت کار با Studio

صفحه را به دو بخش تقسیم کنید:

- داده‌هایی که کاربر باید ببیند، مثل مقدار فعلی و تاریخچهٔ آن
- actionهایی که کاربر باید انجام دهد، مثل تغییر وضعیت، بازکردن صفحه یا انتخاب دستگاه

در Studio ابتدا صفحه و widget را می‌چینید، سپس در Inspector منبع داده یا action
را انتخاب می‌کنید. از قرار دادن مقدار ثابت برای دادهٔ دستگاه پرهیز کنید؛ مقدار
ثابت فقط برای متن راهنما، عنوان و empty state مناسب است.

## پیش‌نمایش و انتشار

پیش‌نمایش برای بررسی layout و اتصال binding است. تغییرات تا زمانی که publish
نکنید در تجربهٔ کاربر نهایی دیده نمی‌شوند. قبل از publish در اندازهٔ موبایل و
دسکتاپ پیش‌نمایش بگیرید و actionهای نوشتنی را با یک دستگاه آزمایشی امتحان کنید.

## صفحه‌های سیستمی

تجربهٔ ساخته‌شده می‌تواند صفحه‌ها یا surfaceهای سیستمی مانند انتخاب دستگاه،
تنظیم Wi-Fi، زمان‌بندی و بازنشانی کارخانه داشته باشد. این بخش‌ها با dashboard
عادی یکی نیستند و host موبایل یا PWA آن‌ها را به قابلیت واقعی دستگاه وصل می‌کند.

راهنمای مرحله‌به‌مرحله در [ساخت dashboard](/docs/studio/dashboards) و
[انتشار](/docs/studio/publish) آمده است.
