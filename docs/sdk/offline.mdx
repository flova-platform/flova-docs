# Offline و persistence

قطع شبکه باید بخشی از مدل محصول باشد، نه یک حالت استثنایی.

| سیاست | معنی |
| --- | --- |
| `KeepLatest` | آخرین وضعیت unsynced نگه داشته می‌شود |
| `Drop` | cache تغییر می‌کند اما ارسال عقب‌افتاده ساخته نمی‌شود |
| `Reject` | عملی که delivery لازم دارد رد می‌شود |
| `Persistent` | snapshot محدود پس از reboot باقی می‌ماند |

Persistence ابتدا cache را restore می‌کند. آن را مجوز تغییر خودکار actuator
فرض نکنید. اگر restore سخت‌افزار لازم است، پس از بررسی interlockها آن را صریحاً
اجرا کنید.

همچنین `Device::run()` را مرتب صدا بزنید، از `delay` طولانی پرهیز کنید و queue
را با اندازهٔ bounded طراحی کنید.
