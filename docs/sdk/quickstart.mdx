نمونهٔ زیر برای برنامه‌ای است که Wi-Fi و GPIO را خودش مدیریت می‌کند. برای یک
برنامهٔ کامل‌تر از مثال‌های firmware استفاده کنید و handler را به سخت‌افزار
واقعی وصل کنید.

## ESP32 با PlatformIO

```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
  lib_deps = flova-platform/FlovaSDK@^0.3.8
```

کد پایه:

```cpp
#include <Arduino.h>
#include <WiFi.h>
#include <FlovaEsp32.h>

FlovaEsp32 client;
auto relay = client.datastream<bool>("relay");
auto temperature = client.datastream<float>("temperature");

void setup() {
  WiFi.begin("your-wifi", "your-password");
  pinMode(2, OUTPUT);
  relay.onWrite([](bool enabled) {
    digitalWrite(2, enabled ? HIGH : LOW);
  });
  client.begin();
}

void loop() {
  client.run();
}
```

`onWrite` محل امن اعمال فرمان است. فرمانی که از Console، اپ، schedule یا
automation می‌آید از همین مسیر عبور می‌کند. `run()` را مرتب صدا بزنید تا
پیام‌های صف‌شده و reconnect فرصت اجرا داشته باشند.

## گزارش وضعیت و تغییرات چرخهٔ عمر

برای نمایش وضعیت اتصال یا عیب‌یابی، یک listener ثبت کنید. listener فقط هنگام
تغییر وضعیت فراخوانی می‌شود و از همان loopی اجرا می‌شود که `client.run()` را
صدا می‌زند؛ بنابراین callback باید کوتاه و غیرمسدودکننده باشد:

```cpp
void onFlovaStatus(void*, const FlovaStatusEvent& event) {
  const FlovaStatusSnapshot& status = event.current;

  if (event.kind == FlovaStatusEventKind::LinkChanged) {
    Serial.println(status.linkConnected ? "Flova Link online"
                                        : "Flova Link offline");
  }

  if (event.kind == FlovaStatusEventKind::ErrorChanged &&
      status.errorCode[0] != '\0') {
    Serial.printf("Flova error: %s\n", status.errorCode);
  }
}

void setup() {
  // Wi-Fi setup and datastream handlers come before this line.
  client.setStatusListener(onFlovaStatus);
  client.begin();
}
```

برای خواندن وضعیت فعلی بدون منتظرماندن برای event، از snapshot استفاده کنید:

```cpp
FlovaStatusSnapshot status = {};
client.status(status);

bool onNetwork = status.networkConnected;
bool onFlovaLink = status.linkConnected;
bool readyForDatastreams = status.ready;
```

این وضعیت‌ها یک معنی ندارند:

| API | معنی |
| --- | --- |
| `networkConnected()` / `status.networkConnected` | شبکهٔ محلی در دسترس است؛ در custom firmware خود برنامه مالک آن است. |
| `tlsReady()` / `status.tlsReady` | ساعت و پیش‌شرط TLS آماده است. |
| `connected()` / `status.linkConnected` | کانال Flova Link متصل است. |
| `runtimeReady()` / `status.runtimeReady` | چرخهٔ داخلی SDK به `Runtime` رسیده است. |
| `ready()` / `status.ready` | runtime و binding دستگاه هر دو آماده‌اند. |

`FlovaStatusEventKind` شامل `LifecycleChanged`، `NetworkChanged`،
`LinkChanged`، `ReadyChanged`، `ConfigurationChanged` و `ErrorChanged` است.
هر event هم snapshot قبلی و هم snapshot فعلی را دارد. اگر وضعیت اولیه را
فوراً لازم دارید، `status()` را بخوانید؛ ثبت listener یک event اولیه تولید
نمی‌کند. `errorCode` یک کد محدود و قابل log است، نه payload کامل یا credential.

## ESP8266 با PlatformIO

مسیر پیشنهادی، استفاده از فایل آمادهٔ
`extras/platformio/esp8266/platformio.ini` در
[نسخه‌های منتشرشدهٔ FlovaSDK](https://github.com/flova-platform/flova-firmware/tags)
است. این profile تنظیمات `platform`، برد، کتابخانه و TLS را آماده دارد؛
بنابراین اگر همین profile را کپی می‌کنید، تنظیم اضافه‌ای لازم نیست.

اگر پروژهٔ PlatformIO خودتان را نگه می‌دارید، dependency کتابخانه را در
environment مربوط به ESP8266 قرار دهید:

```ini
[env:nodemcuv2]
platform = espressif8266@4.2.1
board = nodemcuv2
framework = arduino
lib_deps = flova-platform/FlovaSDK@^0.3.8
```

به‌جای `WiFi.h` از `ESP8266WiFi.h` و به‌جای `FlovaEsp32.h` از
`FlovaEsp8266.h` استفاده کنید.

## ESP8266 با Arduino IDE

`FlovaSDK` را از **Tools → Manage Libraries** نصب کنید و برد ESP8266 را
انتخاب کنید. سپس از `ESP8266WiFi.h` و `FlovaEsp8266.h` استفاده کنید.

## سه عملیات اصلی

```cpp
relay.write(true);                 // فرمان محلی
temperature.report(readSensor());  // مشاهدهٔ سنسور
bool last = relay.value();         // cache محلی
```

`write` handler را اجرا می‌کند، `report` فقط مشاهده را ثبت می‌کند و `value`
درخواستی به شبکه نمی‌فرستد. اگر مقدار سخت‌افزار خارج از handler تغییر کرد، آن
را با `report` اعلام کنید.

برای provisioning در برنامهٔ موجود، [راهنمای setup channel](/docs/sdk/provisioning)
را ادامه دهید.

## helperهای کد سفارشی

در پروژه‌های custom می‌توانید به‌جای تکرار الگوی typed API از
`FlovaCustomCode.h` استفاده کنید. این macroها رفتار SDK را تغییر نمی‌دهند:

```cpp
#include <FlovaCustomCode.h>

auto relay = FLOVA_DATASTREAM(client, bool, "relay");
FLOVA_ON_WRITE(relay, [](bool enabled) {
  digitalWrite(RELAY_PIN, enabled ? HIGH : LOW);
});

FLOVA_WRITE(relay, true);                 // فرمان محلی
FLOVA_REPORT(relay, readRelayState());    // مشاهدهٔ سخت‌افزار
bool current = FLOVA_READ(relay);         // cache محلی
bool known = FLOVA_HAS_VALUE(relay);
```

`write` از handler عبور می‌کند و `report` فقط مقدار مشاهده‌شده را اعلام می‌کند.
کلید و نوع stream باید دقیقاً با Device Type یکی باشد.

## آماده‌سازی برای خاموشی برد

برای deep sleep یا خاموشی برد، ابتدا Link را تخلیه کنید. فلووا وضعیت board را
خودش تغییر نمی‌دهد:

```cpp
const FlovaPowerDownStatus status = client.prepareForPowerDown();
if (status == FlovaPowerDownStatus::Ready) {
  // Wi-Fi و wake source را برنامهٔ برد مدیریت می‌کند.
} else {
  client.run();
}
```

در وضعیت `Draining` باید `run()` ادامه پیدا کند. فقط در `Ready` وارد sleep شوید؛
`Busy` یعنی provisioning، configuration، OTA یا factory reset هنوز فعال است.
