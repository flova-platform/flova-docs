فلووا را می‌توان در دو سطح استفاده کرد. در سطح محصول، Console و Studio به شما
کمک می‌کنند نوع دستگاه، داده، automation و dashboard را بسازید. در سطح سخت‌افزار،
SDK و firmware همین مدل را روی ESP32، ESP8266 یا یک برد سفارشی اجرا می‌کنند.

لازم نیست از همهٔ بخش‌ها هم‌زمان استفاده کنید. اگر دستگاهتان از universal
firmware استفاده می‌کند، بخش زیادی از کار سخت‌افزاری از قبل آماده است و شما در
Console رفتار و ظاهر محصول را تنظیم می‌کنید. اگر یک برنامهٔ Arduino یا firmware
اختصاصی دارید، SDK را به همان برنامه اضافه می‌کنید و فقط مرزهای لازم را به
فلووا می‌سپارید.

## مسیر پیشنهادی

1. [مدل ذهنی فلووا](/docs/start/mental-model) را بخوانید تا تفاوت Device Type،
   datastream، دستگاه و dashboard روشن شود.
2. [اولین دستگاه](/docs/start/quickstart) را با universal firmware بسازید.
3. در [Datastreamها](/docs/concepts/datastreams) نام، نوع و جهت هر داده را
   مشخص کنید.
4. اگر منطق دستگاه باید بدون کدنویسی تغییر کند، [Automationها](/docs/console/automations)
   را بسازید.
5. برای طراحی تجربهٔ کاربر به [Studio](/docs/studio/overview) بروید.
6. برای خواندن تاریخچه و ساخت chart، [FlovaQL](/docs/flovaql/overview) را یاد
   بگیرید.

## سه انتخاب مهم

| اگر این وضعیت را دارید | انتخاب مناسب |
| --- | --- |
| برد ESP32 یا ESP8266 دارید و نمی‌خواهید firmware بنویسید | universal firmware |
| برنامهٔ Arduino موجود دارید و کنترل Wi-Fi و GPIO برایتان مهم است | SDK در حالت custom |
| برد صنعتی، PLC، RTOS یا gateway دارید | هستهٔ C++ قابل‌حمل و adapter سفارشی |

در همهٔ این حالت‌ها نام datastreamها و قرارداد داده باید با Device Type هماهنگ
باشد. تفاوت فقط در این است که چه کسی شبکه، provisioning، GPIO، reset و OTA را
مدیریت می‌کند.

<Note>
این مستندات رفتار عمومی محصول را توضیح می‌دهند. مقادیر نمونه، شناسه‌ها و
credentialها ساختگی‌اند و باید با دادهٔ workspace خودتان جایگزین شوند.
</Note>
